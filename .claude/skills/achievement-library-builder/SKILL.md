# Achievement Library Builder — Amy Raygada

A skill for extracting, structuring, and storing Amy's strongest career evidence in a reusable, queryable format — so that tailoring a CV or preparing for an interview doesn't start from scratch each time.

## Golden rules

- Only work with real achievements Amy describes or that already exist in master-cv.md. Never invent metrics or outcomes.
- If a metric isn't known, help Amy estimate it honestly — not inflate it. "Estimated 30% reduction" is better than a made-up precise figure.
- Every achievement should be verifiable by Amy if asked in an interview. Don't write anything she couldn't stand behind.
- Voice rules: no em dashes, direct, no corporate filler.

## What an achievement entry looks like

Each entry in the library has:

**Title:** A short label (e.g. "ETL Migration Accelerator — GCP/Gemini")
**Tags:** Role context, competency area, and JD-match tags (e.g. `[technical][commercial][product]`)
**One-liner:** A single tight sentence usable in a CV bullet or LinkedIn post
**Full STAR version:** Situation / Task / Action / Result — for interview use
**Metrics:** Concrete numbers or honest estimates with a note on confidence level
**Reuse notes:** Where this achievement is most powerful (e.g. "Lead with this for product commercialisation roles; secondary for pure governance roles")

## Workflow

### 1. Capture mode — "Help me document what I just did"

When Amy describes a project or experience:
- Ask 4–5 clarifying questions to pull out the outcome, the scale, and what was specifically Amy's contribution vs. the team's
- Draft the entry in the format above
- Suggest which tags apply
- Flag if any metric seems uncertain and note it as an estimate

### 2. Library review mode — "What achievements do I have for X?"

When Amy is preparing for a specific role or question:
- Pull relevant entries from master-cv.md and any previously built library entries by tag match
- Surface the 3–5 strongest for that context
- Flag any gaps — situations where Amy likely has an achievement but it isn't yet documented

### 3. Quantification mode — "How do I put a number on this?"

When Amy has a real achievement but no clear metric:
- Help her estimate using inputs she does know (team size, time saved, budget managed, users affected, revenue influenced)
- Present the estimate as an estimate — "approximately," "estimated," "roughly" — rather than false precision
- Ask what she'd be comfortable defending in an interview
